# BOM图片行列与型号规格识别

原始问题：浅灰色Excel表格线未被检测到，而重复文字笔画被像素总和算法判成100多条纵线。碎片单元格、Excel行号甚至说明文本又能通过过宽的质量判定。即便恢复列，旧Tesseract仍容易混淆该截图字体中的0/O与Ω/2，并在逐行/逐格启动时耗尽预算。

## 修复

- 检测相对邻域有对比且连续的细线，连接交叉线造成的小断点；支持浅灰线、彩色数量列和贴边裁切。文字密度不会成为表格线依据。
- 查找实际BOM表头，跳过Excel字母标题。不按列数虚构报价表头，无表头时保留第一条有效数据。
- 使用固定版本RapidOCR的随包CPU识别模型，按实际单元格裁切、跳过空格、分开物理换行、按宽高比分批。上传在应用服务器处理，无外部OCR接口。保留基础Tesseract备用路径。
- 保留整行CTC字符预测，从图像物理间距恢复被识别器遗漏的分隔空格；保持厂家型号、封装与参数之间的边界。未对一般型号进行0/O替换。
- 仅在独立数字阻值、后跟误差的明确语境整理Q/Ω，保留m（毫）和M（兆）的大小写。保留OCR原文以及单位整理/不清晰文字提示；数量中的千位空格也会清理。
- 特定三星型号CL31A106M0HNNNE的0/O歧义，按[三星原厂型号页](https://product.samsungsem.com/mlcc/CL31A106MOHNNN.do)核对为CL31A106MOHNNNE并提示。原厂同时列出1206、X5R、10µF、±20%、16V；其他型号字符不套用这一修正。
- 图片自动选列使用规格型号/规格描述列，厂家独立料号列仍可单独选择。物料编码作为原表信息保留，OCR原文/识别提示不加入额外匹配候选。
- 图片仅在成功读入时缓存原始解析表，按文件内容和会员会话隔离；切换输出品牌不重跑OCR，失败仍可重试。未缓存客户价格或匹配结果。

## 验证

`tools/check_bom_image_ocr.py IMAGE --tesseract ENGINE --expected-rows 16 --verify-example --output RESULT.json` 可复核本次截图。示例断言核对11个型号、12条电阻阻值及4条电容的容量/封装/介质/误差/电压，还有数量解析；图片及带客户物料编码的结果只存本地诊断目录，不加入仓库。

隔离回归覆盖浅灰规则线/彩色填充/贴边格线与密集文本、无格线文本、真实表头/无表头第一行、乱码拒绝、毫欧/兆欧以及型号字符保留、选列/原文隔离和成功/失败缓存。

## 正式环境依赖修复

线上验收发现仅更新requirements仍未安装RapidOCR，实际结果退回基础OCR；后台运行状态现检查真实模型启动。`bom_image_ocr_runtime.py`提供仅限图片识别的隔离组件目录（仓库cache/bom-image-ocr-*），安装显式白名单二进制包与无GUI OpenCV，使用独立子进程，父进程的Streamlit/NumPy和业务库不被升级或替换。只有基础环境缺少模型模块时才初始化；安装与推理有超时，安装后执行真实健康推理，健康目录可复用，失败可重试。数据通过本机数值数组传入，禁用pickle；上传不发送到外部识别接口。首次初始化会从PyPI下载软件包及其随包模型。初始化失败不会以基础碎片OCR误报成功。

`--isolated`可验证相同原图经过独立环境的结果。单测另覆盖安装目录约束、二进制白名单和不升级父环境、健康复用、失败重试、数值数据传输及完整条数、初始化失败阻止假成功。Windows Python 3.14仅关闭子进程可选WMI探测，避免依赖安装阻塞。

边界：识别提示是复核辅助，OCR仍无法保证任意模糊图片的字符正确。内部编码、未显示完整的截断列不会被凭空补成厂家型号。高于89个物理行的格线表要求分图上传，防止截断后误报完整识别。

## 2026-10-13：关键字符与型号规格交叉核对

- 保留逐字符置信度及次选字符，不只依赖整段平均分。CTC重复帧使用字符区间的峰值判断，避免把清晰字符的边界帧误报成错误。
- 对含疑似型号/参数的文字行做放大锐化、对比度处理后再识别两次。忽略无意义空格变化，但不忽略m/M、数字、单位变化。结果一致且字符可靠才消除提醒；不同结果保留首次文字并列出需核对内容。
- 一个0/O、1/I、5/S或8/B型号字符，仅当两次独立处理后的结果一致、原型号无法被规则识别、候选型号有已维护规则，且独立印出的至少两项规格（必须包含阻值/容量）全部一致，才允许修复。保留OCR原文及修复前后型号；有效型号之间不做自动替换。缺规格、未知型号、仍有低置信字符、参数冲突均不猜测修复。
- 从独立文字中移除厂家型号后读取规格，再与维护的型号规则对比封装、阻值/容量、误差、介质和耐压。未知规则不伪装成已核对，不修改用户规格。检查只读，不涉及价格或数据库写入。
- 预览增加具体需确认行/内容/字段列表，匹配结果保留图片识别提示；多次读法不一致或型号规格冲突不能被显示成“可推荐”。复核内容加入匹配缓存签名，避免同内容不同识别风险的行共用错误状态。
- 基础OCR备用路径明确标记未完成字符二次核对，保留候选供确认，不宣称已通过增强验证。

这些措施改善错误发现及有充分证据时的型号修复，不构成对任意图片的准确率或100%正确保证。单张示例通过不等于所有品牌/字体/模糊图均通过。

## 截图 Ctrl+V 粘贴

BOM页面保留原有上传/拖拽，并增加可聚焦的粘贴区域。监听用户触发的paste事件，只接收剪贴板中的单张支持格式图片，通过DataTransfer交给同一个文件上传控件，复用登录检查、上传缓存、OCR及手动开始匹配逻辑。未使用后台剪贴板读取、外部上传接口或额外存储。普通文本、Excel单元格文字粘贴以及其他输入框不被接管；多图、空图、超100MB、非支持格式明确提示。组件重新渲染移除旧监听，避免一次粘贴多次上传。

浏览器/系统复制PNG可能重新编码压缩数据，验收应检查画面像素以及实际上传数据与剪贴板数据相符，不能错误地要求与原始PNG文件压缩字节的哈希相等。原生Ctrl+V验收另外覆盖普通文本及重复粘贴；正式页面需验证粘贴后出现实际BOM预览，而不只检查按钮或file-input赋值。

## 原图定位、人工修正与完整性检查

- 保存每条已提取记录及每个字段在原图中的归一化坐标。放大使用未修改的原始图片（正确处理EXIF方向），不使用缩放后的OCR坐标直接裁切原图。无法可靠定位的基础识别结果只能查看完整原图。
- 图片预览可修改数据字段、逐行人工确认，必须点击保存；Enter只结束单元格编辑，不提交整张修正表。OCR原文、物理行号不可覆盖。所有修改与确认绑定源表指纹、上传内容和当前会员；用户切换、同名文件替换或识别源变化后拒绝套用旧修改。
- 人工修改保留前后值，重新执行型号/规格冲突检查。勾选人工确认可以解除原识别置信提醒，但不能消除仍然存在的参数冲突；未人工确认的修改仍需确认。支持恢复最初识别内容。
- 修正进入工作簿及逐行匹配缓存签名，并随同既有会员隔离的BOM任务settings保存与恢复。原始图片不被改写，价格/会员/未匹配资料不做任何迁移；没有增加业务库schema。
- 对照物料区域的实际有字物理行与被保留的记录。发现跳过的数据行、字符贴边或下缘表格未闭合且有物料文字时明确提醒，疑似漏行不开始完整BOM匹配。未知字符不凭空补字。空白报价列上的浮动Excel工具栏不计为物料行。
- `tools/check_bom_image_matrix.py --font FONT --font FONT --chinese-font CJK_FONT --isolated --output REPORT` 生成非客户资料的8品牌合成表格，覆盖两字体、原图/JPEG75/缩小且轻微模糊共48条型号与规格案例。报告区分准确提取、错误已提醒、错误未提醒，不把单张图片或合成样本当作普遍准确率保证。
- 参数矩阵还暴露TDK混合描述的独立封装被型号内公制码抢占：`C1608... 0603`曾把1608当成inch。现在优先独立印出的封装码，公制显式上下文与既有换算规则保留；不改变纯料号原厂编码含义。原图验证之外另核对全部显式规格，不只统计型号字符。
- 正式手动修正验收发现：保存及风险摘要已更新，但静态预览只按文件/分页/紧凑模式缓存，仍显示旧规格。预览缓存现包含当前表格内容指纹；同文件下修改字段、人工确认、恢复初始内容都会刷新，未变化的表继续复用，缓存仍只保留当前一份。不清空识别源缓存或用户修正，也不改写OCR原文。

## 图片预览简化

- 用户认为四个独立展开栏与重复原文/长说明让主流程混乱。图片主页面改为识别数据预览、短提示及一个默认收起的“识别有误？修改”入口；删除图片主页面的长技术提示和单独定位按钮。Excel/CSV原有预览、选列入口与流程不改。
- 只从显示副本中隐藏OCR原文/行号/长提示及全空字段，不删除实际识别表、匹配证据或任务记录。疑问行显示短提示及浅黄色背景，已确认行恢复正常底色；不依赖颜色单独表达风险。原表若自有“提示”列，保留它并另命名核对提示，避免覆盖业务信息。
- 图片匹配后的页面结果也隐藏重复OCR字段，保留实际匹配状态/风险说明、价格及空价格列；完整结果与下载数据不做删列。
- 原图放大/完整图、编辑/保存/恢复、人工确认、手动调整匹配列和详细原因在同一个入口的三个标签页内。无嵌套展开栏，兼容旧Streamlit。只有整段文字的基础识别结果提供独立可编辑的“规格型号”列，初值与原文完全相同；旧原文保留，原先指向原文的规格映射改指该副本，以便实际匹配采用人工修正值。
- 字符二次核对、型号规格冲突、漏行阻止匹配、未确认降级、会员/文件隔离及修正保存恢复等保护保持生效。界面简化不把未验证的识别结果变成“已确认”。

## 上传和粘贴合为一个区域

- 删除独立粘贴按钮和占位行。保留原生Streamlit文件上传控件，在它自己的区域内加入中文上传按钮及点击/拖拽/页面Ctrl+V提示；区域可聚焦并用Enter/空格打开文件选择。文件选择器、原生拖拽、权限、大小检查和既有读取/匹配流程不替换。
- 粘贴事件接收Excel/CSV及支持格式图片的真实File对象，保留文件名/字节。普通文本不变，输入框、表单和编辑表格中的混合文字/图片粘贴不接管。只在用户触发paste时读取内容，不后台访问剪贴板，不读取客户端文件路径，不增加外部上传接口。
- 同源外层代理页面也接收用户paste，避免必须点击一个专用粘贴按钮。状态与异常提示位于原上传区域内部，新的点击选择/拖拽会清除旧粘贴错误。多文件、非支持格式、空文件、超100MB明确拒绝。重渲染及离开页面清理监听/观察者/样式与区域属性，保留一个控制器。
- 系统复制文件能否粘贴取决于浏览器实际暴露的文件内容；仅提供路径或空文件列表时，不把路径当文件上传，提示使用同一区域点击/拖拽。依据：[MDN DataTransfer.files](https://developer.mozilla.org/en-US/docs/Web/API/DataTransfer/files)。本地headless测试原生图片Ctrl+V通过，文件事件与真实字节上传通过，但OS文件剪贴板未产生可用文件，不能据此宣称所有浏览器都支持资源管理器复制文件。
- 入口缓存增加仅含界面逻辑的剪贴板模块文件指纹，并在缓存失效时重新载入该无状态模块。会员/业务运行模块不重新加载，避免线上热更新仍显示旧粘贴按钮。
- 新Streamlit上传后会把删除文件按钮放在新增上传按钮之前；上传样式仅用于新增上传动作，排除文件卡片/删除按钮，保留原有移除功能。窄屏强制横向可换行布局，避免提示区域的flex-basis被当成高度。
