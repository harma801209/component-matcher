# BOM图片行列与型号规格识别

原始问题：浅灰色Excel表格线未被检测到，而重复文字笔画被像素总和算法判成100多条纵线。碎片单元格、Excel行号甚至说明文本又能通过过宽的质量判定。即便恢复列，旧Tesseract仍容易混淆该截图字体中的0/O与Ω/2，并在逐行/逐格启动时耗尽预算。

## 修复

- 检测相对邻域有对比且连续的细线，连接交叉线造成的小断点；支持浅灰线、彩色数量列和贴边裁切。文字密度不会成为表格线依据。
- 查找实际BOM表头，跳过Excel字母标题。不按列数虚构报价表头，无表头时保留第一条有效数据。
- 使用固定版本RapidOCR的随包CPU识别模型，按实际单元格裁切、跳过空格、分开物理换行、按宽高比分批。上传在应用服务器处理，无外部OCR接口。保留基础Tesseract备用路径。
- 保留整行CTC字符预测，从图像物理间距恢复被识别器遗漏的分隔空格；保持厂家型号、封装与参数之间的边界。未对一般型号进行0/O替换。
- 仅在独立数字阻值、后跟误差的明确语境整理Q/Ω，保留m（毫）和M（兆）的大小写。保留OCR原文以及单位整理/不清晰文字提示；数量中的千位空格也会清理。
- 特定三星型号CL31A106M0HNNNE的0/O歧义，按[三星原厂型号页](https://product.samsungsem.com/mlcc/CL31A106MOHNNN.do)核对为CL31A106MOHNNNE并提示。原厂同时列出1206、X5R、10µF、±20%、16V；其他型号字符不套用这一修正。
- 图片自动选列使用规格型号/规格描述列，厂家独立料号列仍可单独选择。物料编码作为原表信息保留，OCR原文/识别提示不加入额外匹配候选。
- 图片仅在成功读入时缓存原始解析表，按文件内容和会员会话隔离；切换输出品牌不重跑OCR，失败仍可重试。未缓存客户价格或匹配结果。

## 验证

`tools/check_bom_image_ocr.py IMAGE --tesseract ENGINE --expected-rows 16 --verify-example --output RESULT.json` 可复核本次截图。示例断言核对11个型号、12条电阻阻值及4条电容的容量/封装/介质/误差/电压，还有数量解析；图片及带客户物料编码的结果只存本地诊断目录，不加入仓库。

隔离回归覆盖浅灰规则线/彩色填充/贴边格线与密集文本、无格线文本、真实表头/无表头第一行、乱码拒绝、毫欧/兆欧以及型号字符保留、选列/原文隔离和成功/失败缓存。

## 正式环境依赖修复

线上验收发现仅更新requirements仍未安装RapidOCR，实际结果退回基础OCR；后台运行状态现检查真实模型启动。`bom_image_ocr_runtime.py`提供仅限图片识别的隔离组件目录（仓库cache/bom-image-ocr-*），安装显式白名单二进制包与无GUI OpenCV，使用独立子进程，父进程的Streamlit/NumPy和业务库不被升级或替换。只有基础环境缺少模型模块时才初始化；安装与推理有超时，安装后执行真实健康推理，健康目录可复用，失败可重试。数据通过本机数值数组传入，禁用pickle；上传不发送到外部识别接口。首次初始化会从PyPI下载软件包及其随包模型。初始化失败不会以基础碎片OCR误报成功。

`--isolated`可验证相同原图经过独立环境的结果。单测另覆盖安装目录约束、二进制白名单和不升级父环境、健康复用、失败重试、数值数据传输及完整条数、初始化失败阻止假成功。Windows Python 3.14仅关闭子进程可选WMI探测，避免依赖安装阻塞。

边界：识别提示是复核辅助，OCR仍无法保证任意模糊图片的字符正确。内部编码、未显示完整的截断列不会被凭空补成厂家型号。高于89个物理行的格线表要求分图上传，防止截断后误报完整识别。
